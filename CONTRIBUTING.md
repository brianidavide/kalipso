# Contributing

Thank you for helping. Original code is AGPL-3.0-or-later; contributors keep their copyright and no assignment is requested. Keep third-party notices intact.

## Layout

| Path | Contents |
| --- | --- |
| `src/` | Standalone Qt app (`window`, `reader`, `library`, `import`, `remote`), shared tracker, speech service and the `kalipso-engine` companion (`src/engine`) |
| `desktop/` | Plasma widget, GNOME extension and the shared JavaScript tracker (`desktop/*.mjs`) |
| `site/` | Static website |
| `tests/` | Qt tests, frontend runtime tests and fixtures |
| `tools/` | Installers, generators and repository checks |
| `translations/` | Qt Linguist translations of the standalone app |

The tracker exists twice, in C++ (`src/tracker.cpp`) and JavaScript (`desktop/tracker.mjs`); change both and their tests together. `desktop/*.mjs` are the sources for the copies in `desktop/plasma/contents/ui/` and `site/assets/`: edit them, then run `python3 tools/sync-shared.py`. Design values live in `design/tokens.json`; regenerate derived files with `python3 tools/generate-design-tokens.py`.

C++ follows `.clang-format` (`clang-format -i` on the files you touch).

## Build and test

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

CTest runs the Qt tests (offscreen), the JavaScript tracker in Node and — when `qmltestrunner` and `gjs` are installed — in the real QML and GJS engines used by Plasma and GNOME. On Debian and Ubuntu, `gjs qml6-module-qttest qml6-module-qtqml-workerscript qt6-declarative-dev-tools` provide those. To run the UI tests on a real X11 server as CI does:

```sh
xvfb-run -a env QT_QPA_PLATFORM=xcb build/ui_tests
```

### Checks

- `python3 tools/check-repository.py`: only source and distribution files are tracked.
- Website: `npm ci --prefix tools/browser && tools/browser/node_modules/.bin/playwright install --with-deps`, serve `site/` on port 8770 (`python3 -m http.server 8770 --directory site`), then run `PLAYWRIGHT=tools/browser/node_modules/playwright/index.mjs AXE_CORE=tools/browser/node_modules/axe-core/axe.min.js node tools/check-accessibility.mjs` and `node tools/check-design.mjs`.
- Speech changes: check alignment, latency, resource use and start/stop behaviour. `benchmarks/` has the probes.
- Speaker-note fixtures in `tests/fixtures/` are generated by `tests/fixtures/make-presentations.py` with LibreOffice.

Use synthetic test data. Never commit recordings, transcripts, models, API keys, packages, screenshots (other than curated `site/assets/media/`) or machine-specific configuration; put local output under the ignored `artifacts/`.

## Translations

```sh
lupdate -no-obsolete -locations none src -ts translations/kalipso_it.ts
```

Open the `.ts` file in Qt Linguist, translate, and rebuild. Add a language by creating `translations/kalipso_<code>.ts` and listing it in Settings → Interface language (`src/window.cpp`).

The Plasma widget (`i18n()`) and GNOME extension (`_()`) share one gettext catalog in `desktop/po/`:

```sh
cd desktop
xgettext --from-code=UTF-8 --language=JavaScript --keyword=i18n --keyword=_ --no-location \
  -o po/kalipso-desktop.pot plasma/contents/ui/*.qml gnome/*.js
msgmerge --update po/it.po po/kalipso-desktop.pot
```

`desktop/package.py` compiles every `po/<language>.po` into both packages.

## Dependencies and CI

Build-tool versions are pinned in `tools/dependency-versions.json` (Qt, Node, Python, CMake, aqt) and GitHub Actions are pinned to commits. `python3 tools/check-dependencies.py` and a weekly workflow report newer stable releases without changing anything. Linux CI builds against both the distribution's Qt and the latest stable Qt; macOS and Windows CI build, test and package the standalone app. Windows temporarily installs aqt from an upstream commit because aqt 3.3.0 cannot locate the Qt 6.11+ Windows repositories (#1).

## Releases

1. Update `project(Kalipso VERSION …)` in `CMakeLists.txt`, the AppStream `<release>` entry and the Plasma/GNOME `metadata.json` versions.
2. Push a tag `vX.Y.Z` matching that version. The release workflow builds the Linux `.deb` and tarball, the macOS and Windows archives and the Plasma/GNOME packages, and creates a **draft** release with `SHA256SUMS`.
3. Check the draft and publish it. Packages are not yet signed or notarized.

## Reporting problems

Describe how to reproduce the problem and include your desktop and version, Qt version, speech engine and audio setup.
